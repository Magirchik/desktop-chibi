# DesktopChibiBridge для Vesktop (Linux)

Мост передаёт состояние речи выбранных User ID в одном выбранном голосовом канале. Не открывает микрофон, не записывает звук, не читает сообщения и не использует токен Discord. Плагин не отправляет сообщения другим людям.

## Что подготовлено

- `DesktopChibiBridge/index.ts`: проверяет выбранный голосовой канал и состояние речи разрешённых пользователей раз в 250 мс; отправляет изменения и обновления раз в 2 секунды.
- `DesktopChibiBridge/native.ts`: читает один приватный конфиг Desktop Chibi и отправляет разрешённые состояния через Unix-сокет текущего пользователя. Никаких сетевых портов; токен локального источника не передаётся браузерной части.
- `.tools/vesktop-release`: собранный Vencord для Vesktop с плагином, лицензиями, исходниками плагина и `build.json` с коммитом/контрольными суммами.
- `install.py`: сначала показывает план; запись выполняется только с `--install`. Сохраняет резервные копии, настройки остальных плагинов, чибиков и правил.

## Установка подготовленной сборки

Из корня проекта:

```sh
.venv/bin/python integrations/vesktop/install.py --target-id ID_ЧИБИКА
```

Проверьте имя чибика, Channel ID и User ID в плане. Они берутся из уже сохранённой настройки Discord (или существующего моста). Для других значений используйте быструю настройку приложения после установки.

Полностью завершите **Desktop Chibi и Vesktop** через их меню «Выход». Закрытие Vesktop завершит текущий звонок. Затем:

```sh
.venv/bin/python integrations/vesktop/install.py --target-id ID_ЧИБИКА --install
```

Установщик копирует сборку в личный каталог данных и меняет `vencordDir` в `~/.config/vesktop/state.json`, включает только новый плагин `DesktopChibiBridge`. Системный `/opt/Vesktop` не изменяется. Существующая подходящая RPC-привязка выбранного чибика переносится на мост; источник RPC выключается, если у него больше нет включённых правил. Облик и остальные настройки чибиков сохраняются.

Запустите Desktop Chibi и Vesktop. В Vesktop откройте **Настройки → Vencord → Плагины → DesktopChibiBridge** и убедитесь, что он включён. Войдите в разрешённый голосовой канал. В Desktop Chibi: **Источники → Vesktop → Состояние** должно показать подключённый плагин. Попросите выбранного друга заговорить.

Для изменения фильтров: выберите чибика → **Облик → Речь друга в Vesktop…**. Нужны только Channel ID, User ID и анимация. Токен аккаунта, OAuth и Client ID не нужны. Наличие клипа `talk` проверяется в мастерской: без него показывается индикатор речи на существующем персонаже.

## Файлы и отзыв доступа

Desktop Chibi создаёт `~/.config/DesktopChibi/vesktop-bridge.json` (или внутри `XDG_CONFIG_HOME`) с правами `0600`, когда разрешён источник Vesktop и открыт локальный канал. Файл содержит только ключ локального моста, выбранный канал и разрешённые User ID. Плагин читает этот фиксированный путь; произвольных путей или адресов в его API нет. Сервер повторно проверяет ключ, пользователя и канал. При отключении источника/выходе файл удаляется, при потере связи реакции снимаются; действует и автостоп правил.

Чтобы отключить мост, выключите источник Vesktop в Desktop Chibi или отключите плагин в Vesktop. Для возвращения к штатному Vencord закройте Vesktop и восстановите прежнее поле `vencordDir` из созданной рядом резервной копии `state.json.before-chibi-bridge-*.bak` (если его раньше не было — удалите это поле). Остальные изменённые после установки настройки сохраняйте; не заменяйте весь JSON старой копией без необходимости. «Force Update Vencord» может перезаписать пользовательскую сборку — для обновления моста нужна пересборка с плагином.

## Сборка и проверки

Официальный workflow пользовательских плагинов: [Vencord Docs](https://docs.vencord.dev/installing/custom-plugins/). Скопируйте каталог плагина в `src/userplugins/DesktopChibiBridge.vesktop` в исходниках Vencord, установите зависимости по lockfile и выполните `pnpm build --standalone`. Проверьте `pnpm testTsc`. Нативный IPC API следует [документации Vencord](https://docs.vencord.dev/plugins/native/).

В этом проекте: `node integrations/vesktop/tests/renderer.test.mjs` проверяет переходы речи, пользователя, смену канала и выключение плагина. Python-тесты `test_vesktop_bridge.py` проверяют реальную доставку Node → Qt IPC → анимация, закрытый ключ, блокировку чужих ID, потерю связи, миграцию и установку в временный профиль.

Для моста Vesktop пустой **Channel ID** включает автоматический выбор текущего голосового канала. При переходе в другой канал, выходе и повторном входе отслеживание разрешённых User ID продолжается автоматически. Заполненный Channel ID ограничивает реакцию одним каналом.

**Видимость по присутствию друга (Vesktop):** для выбранного чибика включите «Экран → Показывать только когда друг в моём звонке». Используются разрешённые User ID из его включённых личных правил речи Vesktop. При нескольких друзьях достаточно присутствия одного. Молчание не скрывает персонажа. При выходе из канала или потере связи с мостом персонаж скрывается; при возвращении появляется, если не был скрыт вручную. Положение, анимации и ручная видимость сохраняются независимо от временного скрытия. Требуется обновлённый DesktopChibiBridge с передачей присутствия. Установщик включает этот режим для целевого чибика.
