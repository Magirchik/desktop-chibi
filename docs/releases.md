# Windows, Ubuntu и релизы

[← На главную](../README.md)

## Готовые сборки

| Платформа | Файл | Запуск |
| --- | --- | --- |
| Windows 10/11 x64 | `desktop-chibi-vX.Y.Z-windows-x64.zip` | Распаковать всю папку, запустить `desktop-chibi.exe` |
| Ubuntu 22.04+ amd64 | `desktop-chibi-vX.Y.Z-ubuntu-amd64.deb` | `sudo apt install ./имя-файла.deb` |
| Linux x64, переносной вариант | `desktop-chibi-vX.Y.Z-ubuntu-x64.tar.gz` | Распаковать, запустить `desktop-chibi/desktop-chibi` |

Сборки содержат Python, Qt, картинки и шрифты. В Windows не перемещай `.exe` отдельно от `_internal`. Пакет Ubuntu устанавливает программу в `/opt/desktop-chibi` и добавляет ярлык с зайчиком в меню приложений. Удаление — `sudo apt remove desktop-chibi`.

Рядом со сборками находятся `SHA256SUMS` и `build-*.json`: контрольные суммы, версии Python / Qt и результаты проверки запуска. Linux-сборка CI выполняется на Ubuntu 22.04; пакет фиксирует минимальную glibc среды сборки.

## Что работает на каждой платформе

| Возможность | Windows | Ubuntu / Linux |
| --- | :---: | :---: |
| Чибики, темы, пресеты, GIF и редактор | ✓ | ✓ |
| Таймеры и локальные события `--emit` | ✓ | ✓ |
| Глобальные хоткеи | Win32 RegisterHotKey | Портал рабочего стола |
| Правила активного приложения | Win32, без опроса окон | Мост GNOME |
| Свой звук | WAV / PCM, WinMM | WAV / OGG / FLAC, pw-play или paplay |
| Системные уведомления Linux | — | ✓ |
| Состояние звука PipeWire | — | ✓ |
| Текущий плагин Vesktop | — | ✓ |

Настройка хоткеев в Windows находится во вкладке «Управление». Сочетания сохраняются, нажатия обрабатываются внутри приложения без отдельного процесса и без опроса клавиатуры. Если новое сочетание занято, предыдущие рабочие сохраняются.

Windows-правила используют имя исполняемого файла без `.exe`, например `firefox`; список можно получить кнопкой «Обновить список». Защищённые системные процессы могут не сообщать своё имя обычному пользователю.

## Автоматическая сборка на GitHub

Workflow **Windows and Ubuntu releases** запускается при изменениях `main`, тегах `v*`, pull request и вручную в **Actions → Run workflow**.

1. Отдельные раннеры Windows Server 2022 и Ubuntu 22.04 устанавливают Python 3.12 и зависимости сборки.
2. Выполняются тесты. Проверки Linux-портала и плагина Vesktop пропускаются на Windows.
3. PyInstaller создаёт отдельную папку приложения для каждой ОС.
4. Готовое приложение запускается с `--self-test` из постороннего каталога: проверяются Qt, изображения, шрифты, мастерская и темы. В Windows дополнительно проверяются регистрация хоткеев, подключение событий активного окна и загрузка WinMM.
5. Создаются ZIP, TAR.GZ, DEB и манифесты. Они доступны в артефактах Actions.
6. После успешных сборок обеих ОС workflow основной ветки готовит **черновик релиза**. Pull request ничего не публикует.

Для workflow используется встроенный `GITHUB_TOKEN`; свой токен в файлы проекта добавлять не нужно. Черновик виден владельцу репозитория в **Releases**. После проверки скачанных приложений нажми **Publish release**.

## Выпуск следующей версии

Измени `__version__` в `desktop_chibi/__init__.py`, например с `0.1.0` на `0.1.1`, затем отправь изменения в `main`. Workflow подготовит новый черновик с обеими сборками.

Можно также создать соответствующий тег:

```sh
git tag v0.1.1
git push origin v0.1.1
```

Тег должен совпадать с `__version__`; несовпадение останавливает сборку. Опубликованный релиз не перезаписывается. Повторная сборка той же неопубликованной версии обновляет её черновик.

## Локальная сборка

Собирать нужно на целевой ОС. Для воспроизводимой сборки используй отдельное окружение с Python 3.12:

```sh
python -m pip install -r requirements-build.txt
python scripts/build_release.py
```

На Ubuntu добавь `--deb`. Результат находится в `release/`, папка приложения — в `dist/desktop-chibi/`. Локальная Linux-сборка требует glibc не старее компьютера сборки, поэтому пакет для Ubuntu 22.04 выпускается именно на раннере 22.04.

В сборках есть папка `licenses` с уведомлениями Qt / PySide и лицензиями зависимостей; шрифты сохраняют собственные лицензии. Локальная сборка сама по себе ничего не отправляет на GitHub.
