# События и интеграции

[← На главную](../README.md)

Начни с **«Помощника настройки…»**. Все ручные параметры находятся в **«События и правила…»**. У источника есть отдельное разрешение; у правила — получатель, событие, анимация и пауза между повторами.

## Системные уведомления Linux

Выбери сценарий **«Сообщения мессенджера»** либо **«Облик → Реакция на уведомления…»**. Укажи приложение через список или **«Поймать уведомление»**, выбери анимацию и сохрани.

Имя приложения в уведомлении может отличаться от имени исполняемого файла. Для точного фильтра нужен `app_name` отправителя. Тексты сообщений отбрасываются. Источник — `notifications`, событие — `message.received`.

## Свой звук

В личном или общем правиле включи **«Проигрывать свой звук»**, выбери WAV / OGG / FLAC и громкость. **«Послушать»** проверяет файл и звуковой выход. Отдельный флажок разрешает звук, когда чибик скрыт; по умолчанию скрытые персонажи молчат.

В Linux используется `pw-play` или `paplay`, один канал на приложение. Процесс существует только во время звука — до 15 секунд, файл до 16 МиБ. Продления активного события не повторяют звук. Ошибки видны в диагностике.

В Windows доступны WAV / PCM через встроенный WinMM: громкость задаётся своему звуковому каналу, отдельный процесс не запускается. Буфер ограничен 15 секундами и 16 МиБ; он освобождается после воспроизведения.

## Таймеры

В помощнике есть обратный отсчёт, периодическое напоминание и чередование работы / перерыва. Они работают, пока приложение открыто. Сохранение настроек событий начинает отсчёт заново; интервалы одного источника общие для его правил.

События: `timer.done` — конец отсчёта / повторное напоминание, `focus.break` — начало отдыха, `focus.work` — возврат к работе. Анимации и звуки можно поменять в правилах.

## Звук приложения

Сценарий **«Звук приложения»** наблюдает состояние выходного потока PipeWire, например `firefox`. Пока поток активен, чибик показывает выбранную анимацию. Пауза, остановка или выключение звука потока прекращают реакцию. Микрофон и аудиосодержимое не записываются; тишина внутри работающего видео отдельно не распознаётся.

Источник — `audio`, событие — `audio.playing`, рекомендуемый режим — «Пока активно», автостоп 6 секунд.

## Завершение команды

Включи сценарий **«Задача или генерация завершилась»**. Мастер создаст реакции на успех и ошибку и даст команду для hook.

```sh
.venv/bin/python -m desktop_chibi.emit --source code --event code.done
.venv/bin/python -m desktop_chibi.emit --source code --run python my_script.py
```

`--run` сохраняет код выхода команды и отправляет `code.done` либо `code.failed`. Завершение генерации определяется явным hook, а не чтением содержимого редактора.

Для своих событий включи источник `custom` или создай локальный источник с разрешёнными именами событий:

```sh
.venv/bin/python -m desktop_chibi.emit --source custom --event voice.speaking --subject friend-id
.venv/bin/python -m desktop_chibi.emit --source custom --event voice.speaking --subject friend-id --stop
```

При режиме удержания повторяй сигнал чаще автостопа. `subject` — ID или метка, не текст сообщения. Внешний инструмент может передавать ключ через `CHIBI_EVENT_TOKEN` и `--token-env`.

## Друг в голосовом канале

- **Vesktop:** [инструкция локального плагина DesktopChibiBridge](../integrations/vesktop/README.md). Передаются присутствие и начало / конец речи выбранных друзей.
- **Discord RPC:** требуется одобренный RPC Client ID и OAuth-доступ `rpc.voice.read`. Токен аккаунта не используется. OAuth-токен хранится только до закрытия программы; Client ID, канал и список участников сохраняются.

Для Vesktop используй `voice.speaking`, анимацию «Говорит», удержание с автостопом 6 секунд. Для Discord RPC — 10 секунд. Скрытие до появления друга не отменяет ручную видимость персонажа.

## Личные и общие правила

Личное правило действует для одного слота; общее — для всех чибиков с реакциями. Личное правило того же события имеет приоритет. Переключение пресета не меняет привязки источников.

Разовая реакция проигрывает хотя бы один цикл. Режим удержания продлевается сигналами активности, `active=false` завершает реакцию. Падение и перетаскивание имеют приоритет. Само событие не показывает вручную скрытого персонажа.

Диагностика хранит 40 событий в памяти: источник, тип, ID / имя приложения и результат правила. Тексты сообщений и токены в журнал не записываются.
