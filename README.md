# Desktop Chibi

Маленький персонаж гуляет вдоль нижнего края рабочего пространства. Python 3.10+ и Qt (PySide6).

Пиксельный интерфейс в духе NEEDY GIRL OVERDOSE: сиренево-розовая палитра, резкие рамки, объёмные ретро-кнопки, пиксельный логотип Pixelify Sans и сгруппированные настройки. Текст стилизован под ретро-интерфейс: компактный DejaVu Sans Mono с кириллицей, небольшие полужирные заголовки и пиксельный светлый акцент. Подписи, кнопки и числовые поля используют одну моноширинную гарнитуру; декоративный Pixelify Sans остаётся в логотипе. Клетчатый фон, пиксельные сердца и оконные заголовки объединяют настройки, мастерскую и редактор кадров. Панели подстраиваются под содержимое выбранной вкладки. Предпросмотр персонажа и числовые значения параметров доступны в настройках. Встроенный зайчик нарисован на сетке 32×32; изображения масштабируются без сглаживания.

## Запуск

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m desktop_chibi
```

На Windows: `.venv\Scripts\python -m pip install -r requirements.txt`, затем `.venv\Scripts\python -m desktop_chibi`.

На Linux процесс называется `desktop-chibi`: в btop нажмите `/` и введите `chibi`.
Столбец памяти показывает потребление приложения, включая обработку хоткеев:
они работают внутри основного процесса. Командная строка
процесса при этом по-прежнему может начинаться с пути к Python.

На Linux установите ярлык в меню приложений:

```sh
.venv/bin/python scripts/install_desktop.py
```

После этого найдите **Desktop Chibi** в меню приложений. Значок с головой зайца
используется также окнами и треем; в GNOME приложение можно закрепить в избранном.
После обновления кода перезапустите приложение, чтобы обновился значок открытых окон.
Ярлык использует `.venv` и абсолютный путь к проекту; после переноса папки запустите
установщик снова. Установка выполняется только для текущего пользователя, без sudo.
Для удаления ярлыка удалите `desktop-chibi.desktop` из `~/.local/share/applications`
и `desktop-chibi.png` из `~/.local/share/icons/hicolor/256x256/apps`
(при заданном `XDG_DATA_HOME` — из соответствующих каталогов внутри него).

## Пресеты чибиков

В блоке «Выбранный чибик» выберите настроенного персонажа, нажмите **«Сохранить пресет»** и задайте имя. Пресет сохраняет рисунок, все анимации, проекты слоёв и настройки движения/отображения. Текстуры копируются в библиотеку, поэтому сохранённый пресет не зависит от исходной картинки. Изменения текущего чибика не перезаписывают пресет автоматически.

Выбор в списке **«Выбрать пресет…»** сразу меняет текущий слот. Быстрая смена также доступна через **ПКМ по чибику → «Сменить пресет»** и меню трея **«Быстрая смена пресета»** (для выбранного слота). Сохраните каждого существующего чибика в свой пресет, чтобы быстро менять их местами. Можно хранить до 128 собственных пресетов; встроенный зайчик доступен отдельно.

Флажок **«Размер и движение из пресета»** включает также гравитацию, монитор и оконный слой. Отключите его для смены только облика и анимаций. ID, имя слота, видимость, режим событий и привязки правил сохраняются. Анимация текущего события при смене прекращается; следующие уведомления используют новый облик. Если правило использует дополнительный idle, новый пресет должен содержать такое же имя состояния.

Меню **«⋯»** позволяет обновить выбранный пресет из текущего чибика, переименовать или удалить его из библиотеки. Удаление не убирает активных чибиков и не удаляет файлы снимка, на которые они могут ссылаться. Пресеты переживают перезапуск; для переноса на другой компьютер экспортируйте набор через мастерскую. Пошаговая помощь есть в «Помощь → Пресеты».

## Начать без сложной настройки

После запуска нажмите **«Помощник настройки…»**. Мастер состоит из трёх шагов:

1. Выберите задачу: просто гулять, сообщения мессенджера, завершение задачи или речь друга в Discord.
2. Выберите чибика (можно создать нового), заполните только относящиеся к задаче поля.
3. Проверьте, какой источник и ограничения будут включены. Для событий нужно явно подтвердить разрешение.

Для завершения задачи мастер сразу создаёт реакции на успех и ошибку и даёт кнопку копирования команды hook. Скопированная команда содержит абсолютный путь к Python и модулю-отправителю и работает из любой папки. Сам hook нужно добавить в свой инструмент; приложение не устанавливает его автоматически. Для Discord по-прежнему нужен одобренный RPC/OAuth-доступ: мастер объясняет ограничения, но не обходит их.

Кнопка **«Помощь»** открывает встроенную помощь: первые шаги, рисование, сообщения, завершение задач, Discord, производительность, разрешения и устранение проблем. Гайды работают без интернета; только явно выбранные ссылки открывают внешнюю документацию. Есть поиск по темам и тексту.

Главные параметры разделены на вкладки **«Облик»**, **«Движение»**, **«Экран»**. Кнопка **«События и правила…»** оставляет доступ ко всем ручным параметрам. Внизу окна всегда доступно показать/скрыть выбранного чибика.

## Напоминания и свои звуки

В **«Помощнике настройки…»** доступны три встроенных сценария: **«Напоминать о перерыве»** (повтор), **«Обратный отсчёт»** (один сигнал) и **«Работа / перерыв»** (например, 25 / 5 минут). Они работают, пока приложение открыто, без чтения внешних программ. Интервалы одного источника общие для всех его правил; сохранение настроек событий запускает отсчёт заново. Пропущенные сигналы не накапливаются в очередь.

В **«События и правила… → Правила»** у каждого личного или общего правила есть **«Проигрывать свой звук»**: выбор файла WAV / OGG / FLAC, громкость, прослушивание и отдельное разрешение звука скрытого чибика. По умолчанию звук выключен. Повторные сигналы удержания не повторяют звук; пауза между уведомлениями учитывается. Общее правило запускает один звук, даже если реагируют несколько чибиков. Пресеты облика не меняют эти настройки.

В Linux используется установленный `pw-play` или `paplay`: один канал, отдельный нативный процесс только во время воспроизведения, максимум 15 секунд и файл до 16 МиБ. Нет постоянно работающего звукового помощника или зависимости QtMultimedia. Ошибка файла или звукового выхода отображается в диагностике. Скрытый чибик звучит только при явно включённом флажке; само событие его не показывает.

## Импортированные GIF

Перетащите GIF в мастерскую или нажмите **«Загрузить файл…»**. В сворачиваемых **«Настройках GIF»** доступны скорость 25–400 %, обрезка по кадрам, обратный порядок и уменьшение размера. **«Туда и обратно»** работает вместе с ними. Исходный файл не меняется, параметры переносятся при экспорте набора. Неверный файл не заменяет рабочую анимацию.

Ползунок под предпросмотром позволяет поставить GIF на паузу и выбрать кадр (для GIF с декодированными кадрами). Уменьшение до 128–256 пкс сокращает расход памяти; покадровый редактор принимает кадры до 256×256. Обработка GIF сохраняет его переменные задержки; преобразование в рисунок использует равномерный FPS. Для обратного проигрывания и обработки сохраняется до 512 кадров и 32 МиБ изображений на клип; большой исходник можно уменьшить или обрезать. Большие GIF без обратного проигрывания могут работать потоком.

## Несколько чибиков

Карточка выбранного чибика показывает его облик, размер, возможность перетаскивания и текущую видимость. Статус различает ручное скрытие, общую паузу, ожидание друга и правило активного приложения. Карточка использует уже загруженные кадры и не прерывает анимации событий.

Раздел **«Выбранный чибик»** позволяет добавить до 32 независимых персонажей. **«+ Добавить»** создаёт встроенного зайчика с настройками по умолчанию, без копирования облика, анимаций и параметров выбранного персонажа. Выберите готовый пресет, загрузите набор или нарисуйте новый облик в мастерской. **«Сброс настроек»** сбрасывает размер, движение и экран только выбранного чибика; его имя, облик, анимации, режим, видимость и правила сохраняются. Сохранённые пресеты не изменяются. Список сверху выбирает, кого редактируют остальные настройки. Размер, монитор, слой, скорость, физика, анимации и видимость сохраняются отдельно. Правая кнопка по конкретному чибику открывает его меню; двойной щелчок выбирает его в настройках. Удаление чибика также удаляет адресованные ему правила.

## Режимы, вес и нагрузка

У каждого чибика есть режим:

| Режим | Вес | Возможности |
| --- | --- | --- |
| Декоративный | 1 | Прогулка, гравитация, idle и собственные анимации |
| С событиями | 3 | Всё перечисленное плюс правила оповещений |

Новые чибики по умолчанию декоративные. Добавление, включение или изменение правила переводит его цель в режим «С событиями». Старые сохранённые чибики без поля режима сохраняют возможности событий. Если вручную выбрать декоративный режим, правила остаются в наборе, но не срабатывают. Повторное сохранение неизменённых правил не отменяет этот выбор.

Вес — **условная оценка нагрузки**, не измерение CPU или памяти. Рекомендованный активный вес — **64**, это мягкий ориентир. Разрешено любое сочетание до **32 чибиков**, в том числе 32 с событиями (вес 96). Скрытые не входят в активный вес. Счётчик показывает количество, активный вес и вес всего набора.

Профили производительности:

| Профиль | Декоративные | С событиями |
| --- | --- | --- |
| Авто | До 15 FPS | До 30 FPS |
| Авто, активный вес > 64 | До 10 FPS | До 20 FPS |
| Экономный | До 10 FPS | До 20 FPS |
| Плавный | До 30 FPS | До 60 FPS |

Падение, приземление и перетаскивание получают до 60 обновлений в секунду независимо от профиля. Это целевые пределы обновления окон; частота самих кадров анимации задаётся отдельно в мастерской. Фактическая частота зависит от компьютера и оконной системы.

Оптимизации: один общий адаптивный таймер вместо таймера на каждого чибика; скрытые персонажи и их GIF приостанавливаются; скрытый предпросмотр не обновляется. PNG/WebP-кадры и небольшие GIF разделяются между экземплярами через общий ограниченный кэш (до 32 МиБ), встроенные пиксельные позы тоже кэшируются. Изменённый файл получает новый ключ кэша. Сохранение набора при движении ползунков объединяется с задержкой 180 мс; переключение, добавление, удаление и выход сохраняются сразу. Правила индексируются по источнику и типу события, поэтому при событии не перебирается весь список.

Большие GIF всё равно могут быть тяжелее маленьких спрайт-листов: их декодеры и скорость не разделяются между персонажами. При торможении выберите «Экономный», уменьшите размеры и число видимых чибиков. Вес сам по себе не гарантирует одинаковую нагрузку для разных текстур.

## События и разрешения

Для ручной настройки откройте **«События и правила…»**:

1. Во вкладке **«Источники»** разрешите нужный источник и задайте его ограничения. Все источники изначально выключены.
2. Во вкладке **«Правила»** добавьте связку **источник → событие → чибик → анимация**. Можно указать точный ID участника / имя приложения, длительность и паузу между повторными реакциями.
3. Нажмите **«Сохранить и подключить»**. «Отмена» не меняет разрешения. Предпросмотр правила запускает только анимацию локально, без подключения источников.

Есть встроенные состояния **«Говорит»**, **«Уведомление»**, **«Готово»**, **«Ошибка»**. Нарисуйте им собственные кадры в мастерской или выберите в правиле другую анимацию, включая дополнительный idle. Реакции не показывают скрытого чибика автоматически; перетаскивание, падение и приземление имеют приоритет. Для неподвижного индикатора выключите ему прогулку.

Режим **«Показать на время»** подходит для сообщений и завершения задач. Пауза между повторами действует на всё правило. Режим **«Пока активно, с автостопом»** подходит для голоса: `active=true` включает/продлевает анимацию, `active=false` выключает. Автостоп защищает от потерянного сигнала окончания. Несколько активных участников учитываются отдельно. Если одновременно сработали разные правила, отображается последнее начатое; после его окончания восстанавливается оставшаяся активная реакция.

### Сообщения из мессенджеров (Linux)

Источник **«Системные уведомления Linux»** использует `dbus-monitor`. Укажите точные значения `app_name` нужных приложений через запятую. Фильтр применяется на шине D-Bus, до разбора уведомлений. Чибики реагируют только на уведомления из этого списка; для разных мессенджеров создайте отдельные правила с фильтром приложения.

**Как узнать имя без угадывания:** в быстрой настройке нажмите «Выбрать приложение / определить имя по уведомлению». Есть список установленных приложений, поиск по нему и выбор файла программы или .desktop. Путь используется только для подсказки имени: исполняемый файл не запускается, его путь не является идентификатором уведомления.

Для точного имени разрешите **временное определение отправителей**, нажмите **«Поймать уведомление (30 секунд)»**, затем получите системное уведомление от нужного мессенджера. Выберите найденное имя и примените правило. Во время этого явно разрешённого поиска наблюдаются имена всех отправителей Notify, тексты отбрасываются. Поиск заканчивается через 30 секунд, при закрытии окна или снятии разрешения. Это отдельный временный режим; рабочий источник по-прежнему фильтрует только разрешённый список приложений.

**Проверка:** в точных настройках источника кнопка «Отправить тестовое системное уведомление» использует сохранённое разрешённое имя. Она помогает проверить весь путь от системной службы до чибика, но не подтверждает, что реальный мессенджер использует такое же имя. Для последнего нужен поиск по реальному уведомлению. Если тест есть в диагностике, но реального события нет, проверьте найденное имя и системные/нативные уведомления мессенджера. Если событие есть, но реакций 0 — режим чибика, фильтр приложения, правило и паузу между повторами.

**Анимация:** быстрый сценарий назначает состояние `notify` («Уведомление»). Его можно нарисовать в мастерской. Если собственного notify нет, поверх текстуры покоя теперь появляется анимированный значок оповещения. Пользовательский клип notify имеет приоритет и отображается без добавленного значка.

Внутренний поток D-Bus содержит уведомление целиком, но адаптер извлекает только имя приложения, остальные поля отбрасывает. Заголовок и текст сообщения не передаются в правила и не сохраняются. Это реакция на системное уведомление, а не чтение истории сообщений: если мессенджер не показывает уведомление, события не будет. `app_name` — метаданные отправителя, не подтверждение личности процесса.

Нужны доступная сессия D-Bus и разрешённый мониторинг. Если окружение запрещает его, состояние источника покажет ошибку; расширение привилегий автоматически не выполняется. Для Windows/macOS этот адаптер не реализован. Структура уведомлений описана в [официальной спецификации freedesktop.org](https://specifications.freedesktop.org/notification/latest-single/#protocol).

### Кто говорит в Discord

Подключение идёт к **локальному Discord RPC**, без чтения звука. Требуются одобренное Discord RPC-приложение и OAuth-доступ со scope `rpc.voice.read`: Discord ограничивает этот scope, поэтому одного установленного клиента недостаточно. Это ограничение описано в [официальной документации OAuth2](https://discord.com/developers/docs/topics/oauth2) и [RPC](https://github.com/discord/discord-api-docs/blob/main/developers/topics/rpc.mdx).

В источнике задайте Client ID, OAuth access token, точный Channel ID, список разрешённых User ID и при необходимости путь IPC-сокета. **Токен аккаунта Discord не нужен и не поддерживается.** OAuth-токен хранится только в памяти до закрытия программы; после перезапуска его нужно ввести снова. Client ID, канал и перечень участников сохраняются. Для повторного подключения нажмите «Сохранить и подключить».

Создайте правило `discord / voice.speaking`, выберите анимацию «Говорит», режим «Пока активно» и автостоп **10 секунд**. Фильтр участника может ограничить правило одним другом; источник в любом случае пропускает только разрешённые User ID. Адаптер подписывается на `SPEAKING_START` / `SPEAKING_STOP` только в указанном канале, проверяет выбранный канал каждые 5 секунд и обновляет активность раз в 3 секунды. При отключении RPC или выходе из разрешённого канала реакции прекращаются. Если одобренного RPC-доступа нет, источник показывает состояние ожидания/ошибки; готового подключения «в один клик» в этом случае нет. Можно использовать свой разрешённый интеграционный мост и локальный источник событий ниже.

### Завершение кода и собственные интеграции

Разрешите локальный источник **`code`** и добавьте правило `code.done → нужный чибик → Готово`. Для ошибки можно добавить `code.failed → Ошибка`. Завершение генерации передаётся явным hook-вызовом из инструмента, который её выполняет; само приложение не определяет конец генерации по окну или содержимому редактора.

```sh
# Вызов в hook после завершения генерации / задачи:
.venv/bin/python -m desktop_chibi.emit --source code --event code.done

# Другой вариант: запустить команду и уведомить по её результату:
.venv/bin/python -m desktop_chibi.emit --source code --run python my_script.py
```

`--run` запускает только явно переданную пользователем команду, без shell; успешный выход даёт `code.done`, другой — `code.failed`. Исходный exit code сохраняется, даже если чибики не запущены или уведомление недоступно. Текст вывода/код не передаются в событии.

Для других инструментов можно разрешить источник `custom` или создать новый через **«+ Локальный источник»**, задать список допустимых типов событий и отдельный ключ. Например:

```sh
.venv/bin/python -m desktop_chibi.emit --source custom --event message.received --subject my-messenger
.venv/bin/python -m desktop_chibi.emit --source custom --event voice.speaking --subject friend-id
.venv/bin/python -m desktop_chibi.emit --source custom --event voice.speaking --subject friend-id --stop
```

Для удержания активности внешний мост должен повторять сигнал чаще заданного автостопа. `subject` предназначен для ID участника/задачи/приложения, не для текста сообщений. Никакие Discord- или мессенджер-мосты автоматически не устанавливаются.

Канал использует локальный сокет/именованный канал Qt, без TCP-порта и удалённого доступа. На Linux и Windows разрешение сокета ограничено текущим пользователем ОС. Для каждого локального источника проверяются включение, отдельный ключ и список событий; неизвестные поля, включая `body`/`content`, отклоняются. Обычная CLI-команда берёт ключ разрешённого источника из настроек текущего пользователя. Для отдельной интеграции задайте `CHIBI_EVENT_TOKEN` и флаг `--token-env`, чтобы не передавать ключ в аргументах команды. Кнопка **«Новый ключ»**, затем сохранение отзывают прежний ключ. Отключение источника закрывает его адаптер и сбрасывает активные реакции.

Это разграничение источников внутри приложения, а не изоляция процессов одного пользователя ОС: процессы с доступом к вашим настройкам могут прочитать локальные ключи. Входящие события умеют только проигрывать анимации; механизм событий не выполняет переданные команды и не отправляет сообщения в мессенджеры.

Вкладка **«Диагностика»** хранит последние 40 принятых событий только в памяти: время, источник, тип, ID/имя приложения, включение/выключение и число реакций. Сообщения, звук, OAuth-токен и ключи в журнал не пишутся. При сбое подключения состояние отображается во вкладке источников.

## Закрепление, область прогулки и пропуск кликов

Для выбранного чибика откройте **«Движение → Закрепить на месте»**, затем перетащите его в нужную точку. Он сохранит положение, включая высоту, после перезапуска, перестанет ходить и падать, но продолжит проигрывать idle и реакции на события.

Включите **«Ограничить область прогулки»**, чтобы задать левую, правую, верхнюю и нижнюю границы в процентах от рабочего пространства выбранного монитора. Чибик гуляет по нижнему краю этой области. Обратный порядок границ допустим; минимальная область равна размеру чибика.

В **«Экран → Пропускать клики сквозь чибика»** можно включить прозрачность для мыши: клики попадут в приложение под персонажем. Чтобы снова перетаскивать его, откройте настройки через значок в трее и отключите этот параметр. Поддержка зависит от оконной системы; на нативном Wayland действуют ограничения размещения окон. Все эти параметры индивидуальны и сохраняются в пресетах.

## Движение и гравитация

Поднимите чибика левой кнопкой мыши и отпустите: он ускоряется вниз, приземляется, затем продолжает прогулку. Во время падения можно снова схватить персонажа. Падение происходит на нижнюю границу выбранной рабочей области, с учётом отступа; столкновений с окнами нет.

В настройках доступны размер, скорость прогулки, сила гравитации, отступ от нижнего края, средний интервал остановок и их длительность. Интервал приблизительный: остановки выбираются случайно. Если idle-анимация длиннее заданной паузы, пауза продлевается до конца анимации. Гравитацию и случайные idle можно отключить отдельно. Если прогулка выключена, персонаж остаётся на месте и проигрывает idle.

Встроенные состояния: ходьба, покой с дыханием и морганием, падение с поднятыми лапами, поза в руке и сжатие при приземлении.

Кнопка **«Настройки по умолчанию»** в разделе «Рабочий стол» возвращает размер, скорость, гравитацию, параметры остановок, монитор и слой к стандартным значениям. Выбранный персонаж и его анимации сохраняются.

## Свой персонаж и анимации

### Нарисовать внутри программы

Внешний редактор не нужен. Откройте **«Мастерская анимаций…» → «+ Создать чибика»**: появится чистый прозрачный холст 32×32. Размер можно выбрать внизу и нажать **«Новый холст»** (16, 24, 32, 48, 64, 96 или 128 пикселей).

- **Кисть, ластик, заливка и пипетка**; палитра, свой HEX-цвет и выбор прозрачности. Правая кнопка мыши стирает независимо от выбранного инструмента. Размер кисти — от 1 до 8 пикселей.
- **Сетка и масштаб** от 1× до 24×. Прозрачность показана шахматным фоном. «Предыдущий кадр» показывает его полупрозрачным под текущим, чтобы проще совмещать позы.
- **«+ Кадр»**, **«Копия кадра»**, удаление и перестановка кадров. Выбирайте кадр на ленте; дорисовывайте движение, сохраняя одинаковые размеры холста. Удаление последнего кадра оставляет один пустой кадр.
- Сдвиг рисунка на 1 пиксель стрелками, отражение по горизонтали/вертикали и очистка текущего кадра. Вышедшие за холст пиксели обрезаются; действие можно отменить.
- **Предпросмотр** анимации, пауза и FPS. На паузе показан выбранный кадр. История до 50 действий: **Ctrl+Z**, **Ctrl+Shift+Z** (или кнопки «Отменить» / «Повторить»). «Новый холст» тоже можно отменить.

**Меню редактора.** «Действия кадра» и ПКМ по кадру открывают операции перестановки и копирования в конец. «Действия слоя» содержит общий слой, перемещение выше/ниже и удаление. Основные добавление, копирование и удаление кадров остаются на виду. Навигация и перемещение отключаются на границах; горячие клавиши сохранены.

**Слои.** «+ Слой» создаёт отдельный рисунок на каждом кадре, **«Действия слоя → Добавить общий слой»** — одну деталь сразу на всей анимации (до 16 слоёв). Например, добавьте общий слой с бантиком: он появится на всех 38 кадрах без перерисовки. Выбирайте слой в списке, меняйте имя, видимость и блокировку, удаляйте и перемещайте выше/ниже. При включении общего режима сохраняется рисунок выбранного кадра; действие можно отменить. «Все кадры слоя» применяет отражение, сдвиг или очистку ко всему выбранному слою. Рисование работает с выбранным слоем; пипетка берёт видимый итоговый цвет.

**Навигация.** Есть номер кадра, переход к первому/последнему, перенос выбранного кадра в начало/конец и копия сразу в конец. Лента сама прокручивается к выбранному кадру. Кадры переставляются одновременно на всех слоях.

| Клавиши | Действие |
| --- | --- |
| B / E / F / I | Кисть / ластик / заливка / пипетка |
| Ctrl+клик / ПКМ | Временно взять цвет / стереть |
| Ctrl+Z / Ctrl+Y или Ctrl+Shift+Z | Отмена / повтор |
| ← / →, Home / End | Предыдущий / следующий, первый / последний кадр |
| Ctrl+← / →, Ctrl+Home / End | Переставить кадр, перенести в начало / конец |
| Ctrl+D / Ctrl+Shift+D | Копия рядом / копия в конец |
| Insert / Shift+Delete | Пустой кадр / удалить кадр |
| Ctrl+L | Добавить общий слой |
| Space, + / − | Пауза / проигрывание, масштаб |

При вводе текста или чисел клавиши редактора не вмешиваются. Справка доступна по кнопке **«Клавиши и слои»**.

**«Туда и обратно»** рядом с FPS проигрывает анимацию до конца и возвращает её к исходной позе в обратном порядке: `1 → 2 → 3 → 2 → 1`. Кадры не дублируются, крайние позы не задерживаются дважды. Этот режим сохраняется в наборе (`pingpong: true`) и работает на рабочем столе. Для загруженного GIF включите этот же режим на вкладке «Анимация» в мастерской: преобразовывать файл в кадры не требуется.

Нажмите **«Готово — в мастерскую»**, задайте имя нового чибика. Рисунок станет его анимацией покоя. Для ходьбы, падения, приземления или дополнительного idle выберите состояние и нажмите **«Редактировать кадры…»**. Если у состояния ещё нет файла, редактор возьмёт рисунок покоя за основу; если и его нет — позу встроенного зайчика. Добавьте копии кадров и меняйте их, наблюдая движение в предпросмотре.

**«Редактировать кадры…»** также открывает существующие спрайт-листы и GIF. Для редактирования поддерживается до 512 кадров размером до 256×256 каждый. GIF преобразуется в кадры с постоянным FPS, рассчитанным по средней длительности исходных кадров; неравномерные задержки GIF при рисовании не сохраняются.

Рисунки остаются черновиками до **«Применить»** в мастерской. **«Отмена»** в редакторе отменяет только текущий рисунок, в мастерской — все изменения набора. После применения новые текстуры сохраняются в каталоге данных приложения и доступны после перезапуска. Исходные файлы не перезаписываются. Новому чибику создаётся отдельный набор, поэтому он не заменяет сохранённые анимации предыдущего персонажа. Экспортируйте его через **«Экспорт набора»**, чтобы получить переносимый JSON и папку текстур. Вместе с PNG сохраняется проект `*.pixel.json` со слоями; поле `project` в наборе указывает на него. Не удаляйте этот файл, если хотите продолжать редактировать слои. Для проигрывания используется готовый PNG, собирать слои каждому чибику не требуется.

### Загрузить готовые файлы

1. Нажмите **«Загрузить облик…»** и выберите PNG, GIF, статический WebP или JSON-набор. Прозрачный фон предпочтителен. Исходный персонаж должен смотреть вправо: при движении влево кадры зеркалятся.
2. Откройте **«Мастерская анимаций…»**.
3. Выберите состояние: покой, ходьба, падение, приземление или в руке.
4. Загрузите файл. Для одиночной текстуры оставьте размеры `0`, число кадров `1`. Для спрайт-листа раскройте «Параметры нарезки и скорости» и укажите ширину и высоту одного кадра, число кадров и FPS.
5. Добавьте дополнительные варианты покоя кнопкой **«+ Вариант»**. Они выбираются случайно во время остановок.
6. Нажмите **«Применить»**. Настройки анимаций сохраняются отдельно для каждого выбранного исходного файла. **«Сбросить»** возвращает встроенного зайчика и его стандартные анимации.

**«Удалить»** в мастерской убирает выбранный дополнительный idle из списка, даже если к нему ещё не назначен файл. Для базовых состояний удаляется назначенная анимация, само состояние остаётся доступным. Остальной набор сохраняется. **«Убрать файл»** очищает только файл, оставляя пункт idle в списке.

**«Сбросить набор к исходному»** возвращает анимации исходного JSON-набора или одиночную текстуру выбранного персонажа; для встроенного зайчика — встроенные анимации. Удаление и сброс в мастерской вступают в силу после **«Применить»**; **«Отмена»** отменяет эти изменения.

Спрайт-листы читаются слева направо, затем сверху вниз. Размеры изображения должны делиться на размеры кадра. Например: лист 256×64, кадр 32×32, 16 кадров, 8 FPS. Все кадры лучше делать на одинаковом прозрачном холсте с ногами внизу по центру — тогда переходы между состояниями не будут прыгать.

GIF использует собственные задержки кадров; ручная нарезка и FPS для него не нужны. **«Туда и обратно»** работает и для загруженных GIF без преобразования: крайние кадры не дублируются, каждый кадр сохраняет исходную задержку. Настройка переносится вместе с экспортом и пресетами. Для обратного хода поддерживается до 512 кадров и 32 МиБ декодированных изображений; большие GIF продолжают работать вперёд в потоковом режиме. Редактирование GIF в пиксельной мастерской по-прежнему преобразует его в кадры с единой средней частотой. Ходьба, падение, поза в руке и покой зациклены. Приземление длится один цикл и затем сменяется прогулкой/покоем. При отсутствии файла состояния используется анимация покоя; если её тоже нет — встроенный зайчик. Для событий notify/success/error поверх пользовательского покоя показывается анимированный значок, чтобы реакция была заметна даже без отдельного клипа. Если свой клип события назначен, он отображается без этого значка. Для одиночной текстуры приложение добавляет лёгкое дыхание, подпрыгивание при ходьбе и сжатие при приземлении. Собственные анимации соответствующего состояния отображаются без этих дополнительных деформаций.

**Предпросмотр в мастерской** показывает выбранную анимацию; «Пауза» останавливает её, «Сначала» возвращает к началу. Загрузка, редактирование и воспроизведение находятся на вкладке «Анимация», создание персонажа, импорт, экспорт и сброс — на вкладке «Набор». Скрытые и приостановленные предпросмотры не запускают таймер обновлений. Предпросмотр в основных настройках показывает текущее состояние персонажа.

## Наборы персонажей

Готовый пример: [examples/mint-bunny/chibi.json](examples/mint-bunny/chibi.json). Загрузите его кнопкой «Загрузить облик…»: это мятный зайчик с отдельными спрайт-листами для всех состояний и дополнительным idle. Можно заменить PNG на свои рисунки, сохранив параметры кадров, или изменить их в мастерской.

В мастерской есть **«Импорт набора»** и **«Экспорт набора»**. Экспорт создаёт JSON и папку `<имя>_assets` с копиями текстур. Передавайте их вместе. Импорт внутри мастерской применяется только после кнопки «Применить»; отмена не меняет персонажа. Исходные изображения, выбранные без экспорта, остаются по своим путям: не удаляйте их.

Минимальный формат набора:

```json
{
  "version": 1,
  "name": "My Chibi",
  "animations": {
    "idle": {"file": "idle.png"},
    "walk": {"file": "walk.png", "width": 32, "height": 32, "frames": 8, "fps": 10},
    "fall": {"file": "fall.gif"},
    "land": {"file": "land.png", "width": 32, "height": 32, "frames": 4, "fps": 12},
    "drag": {"file": "drag.png"},
    "idle_1": {"file": "blink.gif"}
  }
}
```

Пути в JSON отсчитываются от самого JSON-файла. Все состояния необязательны. Дополнительные idle называются `idle_1`, `idle_2` и т. д. Поддерживается до 32 состояний, до 512 кадров спрайт-листа, FPS от 1 до 60.

## Окно и управление

- Выбор монитора и слоя: поверх всех окон, обычный, под обычными окнами.
- Правая кнопка по чибику — меню; двойной щелчок — настройки.
- Меню в системном трее: настройки, скрытие и выход. Если трей доступен, закрытие настроек прячет их; иначе завершает приложение.
- Внизу настроек всегда доступна кнопка «Показать чибика» / «Спрятать чибика», индикатор ONLINE / HIDDEN показывает видимость. На маленьком экране содержимое настроек прокручивается.
- Настройки сохраняются средствами QSettings.

## Linux и ограничения

На Wayland приложение предпочитает XWayland (`QT_QPA_PLATFORM=xcb`), если установлен `DISPLAY`: нативный Wayland не предоставляет обычным окнам свободное позиционирование. Нужны работающий XWayland и системные библиотеки Qt xcb (в некоторых дистрибутивах отдельно устанавливается `libxcb-cursor0`). Явно заданный `QT_QPA_PLATFORM` имеет приоритет.

Слои реализованы оконными флагами Qt и зависят от оконного менеджера. «Под обычными окнами» не встраивает персонажа в обои. Отображение поверх выбранных приложений, обход полноэкранных окон и закрепление на всех виртуальных столах пока не реализованы. На нативном Wayland перемещение может не работать. Панели учитываются через доступную рабочую область монитора. Во время перетаскивания чибик ограничен выбранным монитором; другой монитор выбирается в настройках.

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют Qt offscreen и временные настройки: проверяют физику, рисование и кадры, экспорт/импорт, лимит 32 чибика, общие часы, кэш и профили нагрузки, трёхшаговую настройку и согласие на источники, независимость чибиков, маршрутизацию, отзыв разрешений, настоящий локальный IPC и командный hook. Discord RPC и уведомления проверяются на тестовых событиях, без доступа к реальным аккаунтам, звуку и уведомлениям пользователя. Проверкам IPC нужен доступ к локальным сокетам; в изолированной песочнице он может быть запрещён.

Документация: [оконные флаги Qt](https://doc.qt.io/qtforpython-6/PySide6/QtCore/Qt.html), [QMovie](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QMovie.html).


### Уведомления Telegram и стандартный клип

«Telegram» и «Telegram Desktop» распознаются как один клиент, включая известные ID desktop/GTK/Snap. Другие приложения продолжают проверяться по выбранному точному имени. Источник поддерживает `org.freedesktop.Notifications.Notify`, `org.gtk.Notifications.AddNotification` и backend `org.freedesktop.impl.portal.Notification.AddNotification`. Фильтрация разрешённых имён выполняется на шине до обработки; тексты и заголовки не отправляются правилам и в журнал.

В Telegram включите системные/нативные уведомления, сверните окно и получите настоящее сообщение. Собственные всплывающие окна Telegram не являются системными событиями. После обновления кода полностью завершите Desktop Chibi через трей и запустите снова. Настройку «Telegram Desktop» менять не требуется.

В этой версии проверено настоящее уведомление Telegram с копией сохранённого пользовательского правила: одна реакция `notify`, 38 кадров, полные 4,75 секунды. Разовая реакция теперь длится не меньше одного цикла клипа, включая обратную часть в режиме ping-pong; удерживаемые события сохраняют свой таймаут. Реакция, пришедшая во время падения/перетаскивания, дождётся приземления. Повторные доставки внутри cooldown не перезапускают клип.

Стандартная анимация уведомления встроенного зайчика — исходный пользовательский клип из 38 кадров при 8 FPS, включённый по просьбе его автора: `desktop_chibi/assets/default_notify.png`. Пользовательские `notify` имеют приоритет. Для своего персонажа без `notify` используется его текстура с анимированным значком.

Технические источники: [уведомления Telegram Desktop](https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/platform/linux/notifications_manager_linux.cpp), [GNotification](https://docs.gtk.org/gio/class.Notification.html), [портальный backend Notification](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.impl.portal.Notification.html).


Если раньше в диагностике были пары `→ 1` / `→ 0` с одинаковым временем, это могло быть одним уведомлением: системный посредник пересылал его оболочке, и оба этапа попадали в журнал. Теперь пересылка отбрасывается по цепочке адресов D-Bus (только ограниченные технические метаданные, без текста), а отдельные вызовы клиента остаются независимыми. Проверено на системной доставке через посредник: два этапа дают одно событие. Обычный cooldown продолжает действовать на отдельные события и подписывается в диагностике как пауза между запусками.

В диагностике теперь видно имя целевого чибика и результат: анимация запущена, ждёт приземления, чибик скрыт, декоративный режим, пауза, несовпадение фильтра или недоступная анимация. Добавление декоративного чибика не переносит на него существующие правила; это отдельно проверяется тестом.


### Привязать нарисованную анимацию к Telegram

Выберите чибика, откройте **«Облик → Привязать уведомления к этому чибику…»**. Задайте приложение `Telegram Desktop`, выберите анимацию в списке и подтвердите подключение на последнем шаге. Если разрешено ровно одно приложение, его имя подставляется автоматически. Новая привязка сохраняет остальные правила; повторная настройка той же пары «приложение + чибик» обновляет анимацию, а не добавляет вторую одновременную реакцию. Под мастерской показаны действующие привязки выбранного чибика.

Анимация, созданная в мастерской, сама по себе не включает правило. В точных настройках для Telegram или Firefox нужны **«Системные уведомления Linux → message.received»**. Локальное `voice.speaking` с меткой `firefox` ждёт внешний отправитель `emit` и не подписывается на системные сообщения браузера. Рядом с полями правила теперь объясняется, какие события получает выбранный источник.


## Звук Firefox и других приложений

Выберите нужного чибика → **«Облик → Анимация при звуке приложения…»**. Укажите `firefox` (также подходят Firefox и путь к исполняемому файлу), выберите **«Говорит»** и подтвердите источник. То же доступно через новый сценарий «Звук приложения» в быстрой настройке. В мастерской можно нарисовать собственный клип `talk`; при его отсутствии используется анимированный индикатор на текущем персонаже, включая персонажей с одним событийным клипом.

Источник **audio / audio.playing** использует один `pw-dump -N -m` для наблюдения за состоянием выходных аудиопотоков PipeWire. По умолчанию выключен. Он не открывает микрофон, не записывает и не анализирует аудиосэмплы; названия видео, вкладок и другие свойства потока не сохраняются. Отслеживаются только разрешённые приложения; другие выходные приложения и входные потоки не запускают правила. Нужны Linux, PipeWire и установленный pw-dump.

Режим по умолчанию — **«Пока активно»**, автостоп 6 секунд, без cooldown. Активность обновляется раз в 2 секунды без новых строк журнала, пауза/остановка/удаление потока, его mute и нулевая громкость снимают реакцию. Несколько потоков Firefox объединяются: пока играет хотя бы один, реакция продолжается. Это состояние воспроизведения всего приложения, а не отдельной вкладки или голосовой активности: тишина внутри продолжающегося видео не считается остановкой. Отправка паузы зависит от поведения браузера. При сбое источника реакция снимается; автостоп служит дополнительной защитой от зависшего состояния.

Формат источника: `{"id":"audio","kind":"audio","name":"Звук приложения","enabled":true,"events":["audio.playing"],"apps":["firefox"]}`. У личного правила: `source: "audio"`, `event: "audio.playing"`, `subject: "firefox"`, `animation: "talk"`, `mode: "hold"`, `duration: 6`. Старый локальный `voice.speaking` не слушает звук самостоятельно.

Официальные сведения о [pw-dump и режиме наблюдения](https://docs.pipewire.org/page_man_pw-dump_1.html), [свойствах приложений PipeWire](https://pipewire.pages.freedesktop.org/pipewire/group__pw__keys.html).

## Личные и общие правила

В центре событий на вкладке «Правила» теперь две группы:

- **Личные правила** — выберите чибика, чтобы видеть и редактировать только его реакции. Все старые правила считаются личными; ID и привязки сохранены.
- **Общие правила** — запускаются на всех чибиках в режиме «С событиями». Декоративные остаются без реакций. Добавление общего правила не включает им этот режим автоматически.

Включённое личное правило, подходящее к событию и фильтру приложения, имеет приоритет над общим для этого чибика. Остальные используют общее. Неподходящее или выключенное личное правило не блокирует общее. Cooldown общего правила учитывается отдельно для каждой цели. Источники и разрешения остаются общими для приложения.

«+ Правило» добавляет запись в текущую группу, «Сделать общим / личным» переносит её. Смена группы/выбранного чибика сохраняет черновики остальных записей; «Сохранить и подключить» применяет всё, «Отмена» отменяет все изменения окна. Формат правила дополняется `scope: "personal"` (по умолчанию) или `scope: "global"` (цель `*`). Смена пресета сохраняет личные привязки слота и общие правила.


### Vesktop и Discord RPC

Vesktop предоставляет `discord-ipc-0` через arRPC для Rich Presence. Наличие сокета не подтверждает поддержку `AUTHENTICATE`, `GET_SELECTED_VOICE_CHANNEL` или событий речи. Приложение распознаёт известный ответ READY arRPC и останавливает подключение до отправки OAuth-токена, показывая точную причину вместо общего таймаута. На полноценном Discord RPC сообщения таймаута теперь различают подключение, handshake и OAuth.

Для отслеживания конкретного друга в Vesktop теперь есть локальный плагин DesktopChibiBridge: см. [установку и устройство моста](integrations/vesktop/README.md). Подключение через официальный Discord тоже требует подходящего Application ID и OAuth-доступа `rpc.voice.read`, который ограничивает Discord. ID аккаунта и аккаунтный токен не заменяют эти параметры. Источники: [arRPC в Vesktop](https://github.com/Vencord/Vesktop/blob/main/package.json), [команды arRPC](https://github.com/Vencord/arrpc/blob/1dc801e8ea14d96ce8dccff416417614f058afb8/src/server.js), [Discord OAuth scopes](https://github.com/discord/discord-api-docs/blob/main/developers/topics/oauth2.mdx).


## Мост речи Vesktop

Добавлен сценарий **«Друг говорит в Vesktop»** и кнопка **«Облик → Речь друга в Vesktop…»**. Это отдельный источник `vesktop`, который работает через плагин DesktopChibiBridge и существующий приватный IPC, без HTTP-порта, OAuth и токена аккаунта. Разрешаются конкретные Channel ID и User ID; фильтры повторно проверяются приложением. Выбранная анимация `talk` удерживается только во время речи. Ключ моста автоматически хранится в отдельном файле `0600` и не выдаётся браузерной части плагина. Отключение источника удаляет файл, потеря связи снимает реакции.

Подготовленная сборка и установщик описаны в [integrations/vesktop/README.md](integrations/vesktop/README.md). Сначала доступен просмотр конкретного плана; установка требует закрыть Vesktop и Desktop Chibi, делает резервные копии и сохраняет остальные плагины/правила. Сборка проходит TypeScript и проверку start/stop/канала/пользователя; интеграционный тест использует настоящий Node-клиент и Qt Unix-сокет.

Для моста Vesktop пустой **Channel ID** включает автоматический выбор текущего голосового канала. При переходе в другой канал, выходе и повторном входе отслеживание разрешённых User ID продолжается автоматически. Заполненный Channel ID ограничивает реакцию одним каналом.

**Видимость по присутствию друга (Vesktop):** для выбранного чибика включите «Экран → Показывать только когда друг в моём звонке». Используются разрешённые User ID из его включённых личных правил речи Vesktop. При нескольких друзьях достаточно присутствия одного. Молчание не скрывает персонажа. При выходе из канала или потере связи с мостом персонаж скрывается; при возвращении появляется, если не был скрыт вручную. Положение, анимации и ручная видимость сохраняются независимо от временного скрытия. Требуется обновлённый DesktopChibiBridge с передачей присутствия. Установщик включает этот режим для целевого чибика.

Кнопка **«Проверить и исправить»** рядом с «Правила и источники» сохраняет резервную копию настроек, восстанавливает недостающие User ID Vesktop по включённым правилам и переподключает включённые источники. После проверки показывает причины скрытия чибиков, отключённые источники и недоступные анимации. Путь к резервной копии находится в подробностях результата. Кнопка не включает выключенные источники, не отменяет ручное скрытие и не меняет анимации. Установку/обновление плагина Vesktop она не выполняет.

### Игровой оверлей и простой интерфейс

Во вкладке **«Управление» → «Настроить хоткеи…»** доступны два глобальных действия:
скрыть/вернуть всех чибиков и переключить пропуск кликов всех чибиков. Сочетания
назначаются через системный диалог XDG GlobalShortcuts; предлагаются
`Ctrl+Alt+Shift+F9` и `Ctrl+Alt+Shift+F10`, но окончательные сочетания выбирает система
и показывает приложение. Для хоткеев расширение GNOME не требуется. Нужен Linux
с поддержкой портала (в GNOME 48+). Хоткеи обслуживаются внутри приложения через
системную библиотеку D-Bus и события Qt; отдельный процесс и PyGObject не нужны.
Первая настройка запускается только по кнопке;
после успешного подключения сессия хоткеев восстанавливается при запуске приложения.
Изменить назначение в GNOME можно через «Настройки → Приложения → Desktop Chibi».
Повторное нажатие **«Настроить хоткеи…»** открывает эту страницу GNOME; выберите
«Сочетания клавиш». Изменения подхватываются действующей сессией без отключения хоткеев.
Кнопка **«Выключить хоткеи»** завершает сессию и отключает её автоподключение.

Общее скрытие временное: возвращение сохраняет ручное скрытие отдельных чибиков,
правила присутствия друга и правила окон. Переключение кликов действует на весь набор,
включая игровой оверлей и новых чибиков, до следующего переключения или перезапуска.
Те же действия доступны кнопками и через трей.

На вкладке **«Экран»** у каждого чибика есть правило **«Во всех приложениях»**,
**«Только в выбранных приложениях»** или **«Кроме выбранных приложений»**.
Правило проверяет активное приложение для всего рабочего стола, а не геометрическое
перекрытие окон. Откройте нужные приложения, нажмите «Обновить список» и «Добавить»;
ID также можно вводить по одному на строку. Пустой список в режиме «Только» скрывает
чибика везде, в режиме «Кроме» допускает все приложения. Для показа поверх окон
используйте верхний слой или игровой оверлей. Эти правила принадлежат слоту чибика,
не копируются новому и не меняются при выборе пресета.

Для определения активного приложения в GNOME/Wayland требуется отдельный мост:
см. [мост правил окон](integrations/gnome/README.md). Он устанавливается отдельно
и не нужен для хоткеев. При недоступном мосте чибики с ограничивающими правилами
скрываются; режим «Во всех приложениях» работает без него.

На вкладке «Управление» кнопка «Все чибики поверх игры» включает верхний слой, пропуск кликов и полный размер монитора. На X11/XWayland используется отдельный режим обхода оконного менеджера и редкое поднятие видимых чибиков без запроса фокуса. «Обычный режим» возвращает прежний слой и настройку мыши. Настройка для одного персонажа находится на вкладке «Экран». Скрытые вручную и ожидающие друга чибики не показываются принудительно. На нативном Wayland/в некоторых полноэкранных играх композитор может не разрешать поверхностное окно; показ поверх игры не гарантируется, даже в окне без рамки. Проверяйте в конкретной игре.

Основные настройки разделены на пять вкладок: «Чибики», «Облик», «Движение», «Экран» и «Управление». Общие хоткеи, оверлей, производительность и проверка приложения собраны в «Управлении». Вес и профиль производительности скрыты под «Показать настройки производительности». Общий таймер планирует следующий вызов по ближайшему нужному кадру (для одного персонажа в экономном режиме — около 10 вызовов/с вместо прежних 60); скрытые персонажи не обновляются. Это снижение частоты пробуждений, а не измерение экономии CPU/GPU на конкретном ПК.

Когда скрыты все персонажи, общий таймер кадров полностью останавливается до следующего показа. GIF приостанавливаются сразу при скрытии. Рабочие кадры одинаковых анимаций разделяются между чибиками даже после вытеснения из кэша; кэш неиспользуемых кадров ограничен 8 МиБ вместо 32 и освобождается при общем скрытии. Это лимит кэша, не всей памяти приложения: используемые анимации, окна Qt и редактор требуют дополнительную память. Источники событий, выбранные напоминания и горячие клавиши продолжают работать.
